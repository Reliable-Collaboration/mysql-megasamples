# PLAN: MySQL 9.7 LTS image with well-known sample databases

Planning date: 2026-09-02. Evidence for every claim below is in the OKF v0.2 bundle under [`knowledge/`](knowledge/index.md); links in this document point at those records. Nothing in this plan was built, downloaded (beyond small text files read during research) or executed against a database; steps marked **verify first** name the check the executor runs before relying on the statement.

Executor rules that apply to every step: [executor-discipline](knowledge/runbooks/executor-discipline.md) (privileged fixes are handed to the user, never worked around; every research act creates a source record; every deviation is logged) and [ipv6-and-privileges](knowledge/runbooks/ipv6-and-privileges.md) (IPv6 is the first suspect when a pull or download hangs).

## 1. Executive summary

**Target.** MySQL **9.7 LTS**, the newest LTS line (GA 2026-04-21, supported to 2034 under Oracle's 5+3-year policy). Base image `mysql:9.7.2` (Oracle Linux 9 slim, amd64 and arm64). Upstream 9.7.3 exists since 2026-08-18 but the official image had not published it on 2026-09-02; the executor re-checks with `docker manifest inspect mysql:9.7.3` and bumps the pin if present. Evidence and the rejected alternatives (8.4 LTS, 26.7 Innovation): [target-mysql-version](knowledge/decisions/target-mysql-version.md). MariaDB divergences are noted per dataset (no `JSON` native type, different spatial/`utf8mb4_0900` collations, `mysql_native_password` still present) but MariaDB is not built or tested.

**Image layout.** One database per dataset, lower snake_case names, multi-schema sources flattened to `<schema>_<table>` ([naming](knowledge/decisions/database-naming-convention.md), [schema mapping](knowledge/decisions/schema-to-database-mapping.md)). Two accounts created at build: `demo` (read-only: `SELECT, SHOW VIEW`, plus `EXECUTE` on routines created with `SQL SECURITY INVOKER`) and `admin` (all privileges); `root@'%'` with default password `root` (created in the builder because the official entrypoint's account setup never runs on a baked data directory; `MYSQL_ROOT_PASSWORD` overrides it at start). `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_ONETIME_PASSWORD` and `MYSQL_RANDOM_ROOT_PASSWORD` are not supported by this image. A metadata database `megasamples` holds a `datasets` table (name, tier, upstream version, source sha256, license id, row-count manifest, build id) so provenance is queryable. The core tier is **baked into `/var/lib/mysql`** in a builder stage; the official entrypoint detects the initialized datadir and starts in seconds ([bake-data decision](knowledge/decisions/bake-data-vs-initdb.md)).

**Tiers** ([tier model](knowledge/decisions/tier-model.md), [assignments](knowledge/decisions/tier-assignments.md)):

| Tier | Databases |

**Expected core size.** 1.0–1.3 GB of InnoDB pages (every figure inferred from source sizes; the first build measures them, task E-01), compressed image target ≤ 2 GB including the ~0.6 GB base. Fresh clone target < 150 MB; nothing over 5 MB of data is committed except upstream scripts that are themselves the redistributable artifact.

**Toolchain.** `make` + Docker Compose profiles + BuildKit multi-stage Dockerfile ([orchestration](knowledge/decisions/build-orchestration.md)); Python 3.13 with `uv` (PyMySQL, DuckDB, lxml, sqlglot, mwxml; [stack](knowledge/tools/python-conversion-stack.md)); MySQL Shell 9.7 already inside the official image (`util.importTable`, `util.dumpSchemas`, `util.loadDump` with `deferTableIndexes`; [record](knowledge/tools/mysql-shell-utilities.md)); DuckDB for Parquet/CSV normalization and as the TPC-H/TPC-DS generator ([record](knowledge/tools/duckdb.md)); SQL Server 2022 Developer container **only** for WideWorldImporters (the only datasets with no script/CSV form; [record](knowledge/tools/mssql-server-container.md)); Oracle Database Free container only as an opt-in cross-check (every Oracle schema converts from plain scripts and CSV; [decision](knowledge/decisions/oracle-conversion-path.md)); sysbench-tpcc and ssb-dbgen for TPC-C and SSB. Rejected: MySQL Workbench Migration Wizard (GUI-bound, not reproducible unattended; [record](knowledge/tools/mysql-workbench-migration-wizard.md)) and pgloader (loads into PostgreSQL only; [record](knowledge/tools/pgloader.md)).

**Licensing findings that change the inventory** (details §8): Citi Bike and Divvy may not be redistributed as stand-alone datasets, so they become user-fetched loaders; Stack Exchange's current official dumps carry a login and an LLM-training click-through, so the build uses the last click-through-free archive.org snapshot (2024-04); UCI licenses Iris under CC BY 4.0, not public domain; Titanic (hbiostat) and Enron have permission statements rather than licenses; NYC Open Data's "no restrictions" FAQ conflicts with NYC.gov's all-rights-reserved terms and is an open question; the Oracle sample schemas are MIT (confirmed, not UPL); the newer dbt jaffle-shop seeds have no license and are not vendored.

### 2.2 Build pipeline and Dockerfile

Per-dataset conversion runs on the host through Compose, not inside the Dockerfile, because SQL Server/Oracle containers cannot run inside a `RUN` step and because a single Dockerfile would rebuild every dataset for any change ([orchestration](knowledge/decisions/build-orchestration.md)).

`make <dataset>` (identical shape for every dataset; `scripts/load.py` drives it from `datasets/<name>/dataset.yaml`):

1. `fetch` — `scripts/fetch.py <dataset>` downloads every `manifest.yaml` entry for the dataset into `downloads/`, verifies sha256, writes `<id>.ok`, skips verified files.
2. `convert` — `datasets/<name>/convert/*` turns the artifact into `build/tsv/<table>.tsv` (the TSV contract in [load-data record](knowledge/tools/load-data-infile.md)) plus `build/baseline.json` (row counts, canonical digests, samples, per-column aggregates computed from the typed source values, [checksum method](knowledge/decisions/test-checksum-method.md)).
3. `load` — against the `mysql-build` service (`mysql:9.7.2` with `--local-infile=1 --disable-log-bin`, `secure_file_priv=/var/lib/mysql-files` bind-mounted to `build/tsv`): `schema.sql` → server-side `LOAD DATA INFILE` per table in PK order with `unique_checks=0, foreign_key_checks=0` (strict mode on, so any coercion aborts the load) → `indexes.sql` → orphan checks → `constraints.sql` → `routines.sql` → `ANALYZE TABLE`. Loader rule (applies to every dataset; per-dataset sections do not override it): server-side `LOAD DATA INFILE` in strict mode is the default for every table; only tables of 5 M rows or more (Chicago full, Stack Exchange dba `posthistory`, Wikipedia `pagelinks`) use `util.importTable` (`threads` 4 in CI, 8 on the build machine). LOCAL loads are nonrestrictive and their warnings live in worker sessions, so the guard for those tables is the S4 digest over every column plus the utility's own summary line reporting zero warnings (**verify first** at P-04 that `importTable` prints that summary).
4. `test` — `scripts/verify.py <dataset>` runs stages S3–S7 of §4.
5. `dump` — `mysqlsh -- util dump-schemas <db> --outputUrl build/dump --compression=zstd --threads=8` producing the chunked `.tsv.zst` + DDL format that `util.loadDump` consumes ([Shell record](knowledge/tools/mysql-shell-utilities.md)); `build/dump.sha256` is the content address.

`make image` copies the core datasets' `build/dump/` directories into `docker/context/`, runs `scripts/registry.py` (the only writer of `megasamples.datasets`: it merges `manifest.yaml`, `downloads/*.meta.json` and every `build/baseline.json` into `docker/init/10-registry.sql`; the loader re-runs it per extended dataset) and builds:

```dockerfile
# syntax=docker/dockerfile:1.7
ARG MYSQL_VERSION=9.7.2
FROM mysql:${MYSQL_VERSION} AS builder
COPY docker/my.cnf /etc/mysql/conf.d/megasamples.cnf
COPY docker/init/ /build/init/
COPY docker/context/dumps/ /build/dumps/
RUN <<'SH'
set -euo pipefail
mysqld --initialize-insecure --user=mysql
mysqld --user=mysql --daemonize --skip-networking --local-infile=1 --disable-log-bin \
       --socket=/var/run/mysqld/mysqld.sock --pid-file=/var/run/mysqld/mysqld.pid
S=/var/run/mysqld/mysqld.sock
mysql -S $S -u root -e "ALTER INSTANCE DISABLE INNODB REDO_LOG"
for d in /build/dumps/*/; do
  mysqlsh -S $S -u root --no-password -- util load-dump "$d" --deferTableIndexes=all --threads=8 --skipBinlog=true --resetProgress=true
done
mysql_tzinfo_to_sql /usr/share/zoneinfo | mysql -S $S -u root mysql   # CONVERT_TZ() data, normally loaded by the skipped docker_setup_db
mysql -S $S -u root < /build/init/00-users.sql          # root@'%' (default password root), demo, admin
mysql -S $S -u root < /build/init/10-registry.sql       # megasamples.datasets, generated by scripts/registry.py
mysql -S $S -u root -e "ALTER INSTANCE ENABLE INNODB REDO_LOG"
mysqladmin -S $S -u root shutdown
rm -rf /build
SH

FROM mysql:${MYSQL_VERSION}
COPY --from=builder --chown=999:999 /var/lib/mysql /var/lib/mysql
COPY docker/my.cnf /etc/mysql/conf.d/megasamples.cnf
COPY docker/entrypoint-wrapper.sh /usr/local/bin/
ENTRYPOINT ["entrypoint-wrapper.sh"]
CMD ["mysqld"]
```

Why bake rather than load at first start ([decision](knowledge/decisions/bake-data-vs-initdb.md)): the official entrypoint skips initialization, `MYSQL_ROOT_PASSWORD` checks and initdb.d when `/var/lib/mysql/mysql` exists ([entrypoint source](knowledge/sources/docker-library-mysql-9-7-docker-entrypoint.md)), so start-up is the time mysqld needs to open a datadir, the image-level start-time test is meaningful, and every user gets identical bytes. Init scripts would make first start take minutes (Employees alone is 3.9 M rows) and would re-run on every recreated container. Costs accepted: the image carries InnoDB pages (≈3× the size of compressed SQL) and BuildKit rebuilds the load layer whenever any core dump changes. **Verify first (task P-03):** ownership survives `COPY --chown`, the entrypoint takes the "already initialized" branch, and the anonymous-volume copy of the datadir at `docker run` stays within the 30 s start budget; if not, bake into `/var/lib/mysql-baked` with `datadir=` in `my.cnf` (design B in [docker record](knowledge/tools/docker-build-multistage.md)) or fall back to `.sql.zst` init scripts, which the entrypoint supports natively ([image README](knowledge/sources/docker-library-mysql-readme.md)).

`entrypoint-wrapper.sh` is the single runtime hook: if `DEMO_PASSWORD`/`ADMIN_PASSWORD`/`MYSQL_ROOT_PASSWORD` are set, write `ALTER USER ... IDENTIFIED BY ...` statements to a temp file and append `--init-file=<file>` to the mysqld arguments, then `exec docker-entrypoint.sh "$@"`. Two details the entrypoint forces: it re-execs itself under `gosu mysql`, so the file is created with `install -m 0400 -o mysql -g mysql /dev/null "$f"` before writing (a root-owned 0600 file would fail to open as uid 999, and a world-readable one would leave the passwords in `/tmp` for the life of the container); and each password is single-quoted with every `\` and `'` doubled, so a quote in a password cannot break the statement. The file is removed by a `trap` on exit. Nothing runs after the `exec`, and no `/docker-entrypoint-initdb.d` scripts exist in the image. **Verify first:** `mysqld --verbose --help | grep -- --init-file` on 9.7.2 (the option was not read in the manual this session).

### 2.3 Extended tier delivery

* `docker compose --profile extended up` starts the `mysql` image plus a `loader` container (built from `docker/loader.Dockerfile`) that reads `manifest.yaml`, fetches the listed release assets or upstream files into `./downloads/`, and runs `util.loadDump` (for our published dump assets) or the dataset converter (for upstream-only sources such as BTS or Citi Bike) against the running server. `make load-<dataset>` does the same for a single dataset; `make gen-tpch SF=1`, `gen-tpcds SF=1`, `gen-tpcc W=10`, `gen-ssb SF=1`, `gen-jaffle YEARS=3`, `gen-dvdstore SIZE=medium` run generators.
* Release assets (`data-v<N>` GitHub release, ≤ 2 GiB per file, [limits](knowledge/tools/github-limits.md)) hold our converted `mysqlsh` dumps for datasets whose license permits redistribution (AdventureWorks DW, WideWorldImporters × 2, Employees dumps mirror, Lahman CSV mirror, Stack Exchange dba dump, Enron full dump, Wikipedia dump, Contoso 1m/10m, NYC yellow, Chicago full, BTS months). Citi Bike and Divvy have **no** release asset; their loader downloads from the operators' S3 buckets and shows the license text before proceeding.
* Loading inside the `mysql` container itself is not offered: the conversion tooling lives only in the loader image, and the wrapper hands off to the official entrypoint with `exec`.

### 2.6 Environment guidance for the executor

* **IPv6 first.** Hosts with AAAA records that the build touches: Docker Hub (`registry-1.docker.io`, `auth.docker.io`, `production.cloudflare.docker.com`), `mcr.microsoft.com` (SQL Server image), `container-registry.oracle.com`, `d37ci6vzurychx.cloudfront.net` (NYC TLC), `dumps.wikimedia.org`. IPv4-only: GitHub, `objects.githubusercontent.com`, `archive.org`. On this machine WSL has only link-local IPv6 and `curl -6` fails immediately while `curl -4` succeeds; Docker Desktop's VM has its own stack, so a hanging `docker pull` is the classic symptom ([survey](knowledge/sources/build-machine-environment-2026-09-02.md)). Checklist and request template: [ipv6-and-privileges](knowledge/runbooks/ipv6-and-privileges.md). Most exposed steps: base image pull (P-02), `mcr.microsoft.com/mssql/server:2022-latest` pull (X-02), Oracle Free pull (V-01, optional), NYC TLC Parquet and Wikimedia dump downloads.
* **Privileges.** Any fix needing `sudo` or Docker Desktop settings (daemon.json `ipv6`, DNS, `/etc/gai.conf`, sysctl, apt packages) is described to the user with the template in [executor-discipline](knowledge/runbooks/executor-discipline.md) §1 and waited for. Known upfront: `make jq zstd bzip2 p7zip-full` are missing → one apt request before P-01. Docker group membership and disk (932 GB free) are already fine.
* **Docker Hub rate limits.** Anonymous pulls are capped at 100 per 6 h per IPv4 address; CI logs in with a token ([hub usage](knowledge/sources/docker-docs-hub-usage.md)).

### 3.1 Sakila → `sakila` (core) — [record](knowledge/datasets/sakila.md)

* **Source:** `https://downloads.mysql.com/docs/sakila-db.zip`, 729,654 B, sha256 `e27ed871…7046` (measured this session; no upstream checksum; the file's Last-Modified was 2026-08-31, so drift is possible — [question](knowledge/questions/sakila-download-checksum-drift.md)). Version 1.5. Committed in `datasets/sakila/data/` (BSD-licensed .sql files only; `sakila.mwb` is removed from the zip before commit because it is not open-licensed).
* **Path:** run `sakila-schema.sql` then `sakila-data.sql` unchanged through `mysql --default-character-set=utf8mb4` ([decision](knowledge/decisions/sakila-conversion-path.md)). No conversion, no TSV; Sakila is one of the three native-SQL datasets covered by the documented exception in [test-checksum-method](knowledge/decisions/test-checksum-method.md): the baseline is the upstream-documented counts plus the digests of the first verified load, pinned in `tests/`.
* **Schema:** native. Keeps `GEOMETRY` `address.location` (SRID 0, spatial index), InnoDB FULLTEXT on `film_text`, ENUM/SET/YEAR. Definers: objects get `root@localhost`; views/functions/procedures re-created with `SQL SECURITY INVOKER` by a post-step in `routines.sql` except `rewards_report` (writes a temp table, stays DEFINER=admin, not granted to demo).
* **Indexes:** upstream (16 tables' PKs, FKs, `idx_*`, FULLTEXT, SPATIAL) unchanged. Verification list in `tests/indexes.yaml` generated from `SHOW INDEX` at first load and reviewed.
* **Tests:** counts actor 200, address 603, category 16, city 600, country 109, customer 599, film 1000, film_actor 5462, film_category 1000, inventory 4581, language 6, payment **16044** (not 16049: v1.3 removed five rows), rental 16044, staff 2, store 2, film_text 1000 (inferred); `TRIGGERS`=6, `ROUTINES`=6, `VIEWS`=7; `SELECT address FROM address WHERE address_id=8` = `1566 Inegöl Manor`; `ST_SRID(location)`=0; spatial index exists; FULLTEXT search for `dinosaur` > 0; smoke: rental revenue by store (`SUM(amount)` per store) and top-5 films by rentals, expected values pinned at first load.
* **Size/time:** < 10 MB; < 10 s.
* **License artifacts:** `LICENSE` = Sakila BSD-3 text with Oracle notice ([license](knowledge/licenses/bsd-3-clause-sakila.md)); PROVENANCE lists the zip sha256 and the removal of `sakila.mwb`.

### 3.2 Chinook → `chinook` (core) — [record](knowledge/datasets/chinook.md)

## 4. Testing strategy

Tests run at every stage where a defect can be introduced. The mechanics are fixed in [test-checksum-method](knowledge/decisions/test-checksum-method.md); this section states what runs, when, and with what expected values. Per-dataset expected values are in each dataset's §3 subsection and in `datasets/<name>/tests/`.

### 4.1 Stages and what each stage proves

| Stage | Test | Tooling | Fails the build when |
|---|---|---|---|
| S1 fetch | sha256 of every downloaded artifact equals `manifest.yaml` | `scripts/fetch.py` | mismatch, or checksum absent without `MEGASAMPLES_TRUST_FIRST_FETCH=1` |
| S2 extract | per-table row counts read from the native product or file, written to `build/baseline.json` together with the digests and samples of §4.3 | converter (Python/DuckDB) or a query inside the temporary SQL Server / Oracle container | count differs from the value documented in the dataset record (upstream documentation) unless the record explains the difference |
| S3 load | `SELECT COUNT(*)` per table equals baseline | `scripts/verify.py counts` | any difference not listed in `tests/expected_counts.yaml` as intentional (e.g. dropped history table) |
| S4 content | deterministic samples equal column-by-column; per-table `(COUNT, BIT_XOR(d), SUM(d) MOD 2^64)` equal, with `d = CAST(CONV(SUBSTRING(SHA2(row_text,256),1,16),16,10) AS UNSIGNED)` (the CAST matters: `CONV` returns a string and an uncast `SUM` would be a DOUBLE); per-column aggregates equal | `scripts/verify.py digests` | any mismatch |
| S5 integrity | every planned FK has zero orphans before `constraints.sql`; after it, `ALTER TABLE ... ADD CONSTRAINT` succeeded | `scripts/verify.py fks` | orphan count ≠ documented value |
| S6 indexes | every index in `tests/indexes.yaml` exists with the right columns/uniqueness/type; `EXPLAIN FORMAT=JSON` of each smoke query has no `access_type: "ALL"` on the tables listed in `tests/explain.yaml` | `scripts/verify.py indexes explain` | missing/extra index or unexpected full scan |
| S7 semantics | `tests/smoke.sql` canonical queries return the expected rows in `tests/smoke.expected.yaml` | `scripts/verify.py smoke` | any difference (floats compared with 1e-9 relative tolerance) |
| S8 image | container answers a real `SELECT 1` within the time budget (`mysqladmin ping` reports success even on access-denied and must not be used as the gate); all core databases exist; `demo` can `SELECT` and cannot `INSERT/UPDATE/DELETE/CREATE`; `admin` can; `root` connects over TCP with the default password and, when `MYSQL_ROOT_PASSWORD` is set, only with that one; `CONVERT_TZ('2026-01-01','UTC','America/Chicago')` is not NULL; `CHECK TABLE` passes for every table; `information_schema` size per database within ±25 % of the recorded value (`scripts/verify.py sizes`); `SHA2('a',256)` works (SSL build; `MD5`/`SHA1` are absent, as expected) | `tests/image_test.py` | any failure |

### 4.2 Sample comparison specifics

The sample is: the first 20 and the last 20 rows by primary key, plus every row whose `CRC32(pk_text) % 997 = 0` (max 50). Each column is compared after canonicalisation with special cases asserted explicitly per dataset: DECIMAL scale (money columns must show 4 decimals for SQL Server `money`), floating point (excluded from the digest; compared through per-column aggregates and samples with 1e-9 relative tolerance), JSON (excluded from the digest; compared as parsed objects in `verify.py`), dates near DST boundaries (BTS and NYC TLC contain local times without offsets; they are stored as `DATETIME` and compared as text), year 9999 (SQL Server temporal `ValidTo = 9999-12-31 23:59:59.9999999` is truncated to 6 fractional digits; MySQL's DATETIME upper bound is 9999-12-31 23:59:59.999999), year 0/before 1000 (Oracle dates are all ≥ 1990 in the sample schemas; any value < 1000-01-01 fails the load and must be documented), NULL versus empty string (asserted per column: the converter never turns one into the other; `COUNT(col)` and `SUM(CHAR_LENGTH(col))` catch it), trailing whitespace (padded `CHAR` sources are `RTRIM`med on both sides, everything else preserved), multi-byte characters (`SUM(LENGTH)` versus `SUM(CHAR_LENGTH)` distinguishes bytes from characters and the sample includes at least one row with non-ASCII content for every dataset that has any, listed in the dataset record).

## 5. Indexing strategy

Fixed in [indexing-strategy](knowledge/decisions/indexing-strategy.md); per-dataset index designs are in each §3 subsection and in `datasets/<name>/indexes.sql` + `tests/indexes.yaml`.

* **Sources with declared keys** (all SQL Server, Oracle, Sakila, Chinook, Employees, DVD Store, TPC DDLs): primary keys, unique constraints, foreign keys and secondary indexes are carried across with the same column order. Unsupported constructs and their substitutes: filtered indexes → plain index plus a comment naming the predicate; included columns → trailing key columns when the key stays under 3072 bytes, otherwise dropped; bitmap indexes → B-tree; columnstore → none; partitioned indexes → plain; XML indexes → none (XML stored as TEXT); SQL Server spatial and full-text indexes → MySQL SPATIAL and FULLTEXT where the column type allows.
* **Sources without indexes** (CSV, Parquet, XML, generators): each dataset subsection lists candidate keys (or the surrogate and why), FK-like columns with the lookup table they reference, date columns for range scans, high-cardinality filter columns, and composite indexes justified by the canonical queries, with the expected cardinality of every indexed column taken from the baseline `COUNT(DISTINCT)`.
* **Clustered key**: prefer a monotonically increasing integer primary key (upstream identity or surrogate in source order) so bulk loads append; natural composite keys are loaded pre-sorted; wide tables get the minimum set of secondary indexes because each one carries the primary key.
* **Order of operations**: PK-only DDL → bulk load with `unique_checks=0, foreign_key_checks=0, sql_log_bin=0` → one `ALTER TABLE ... ADD INDEX ...` per table → orphan checks → foreign keys and CHECKs → `ANALYZE TABLE`. The Employees dataset is used to measure the difference between this order and indexes-first (task E-02) and the numbers are written into its record.
* **InnoDB specifics**: monotonically increasing integer clustered keys wherever the source has an identity/surrogate, pre-sorted loads for natural composite keys, minimal secondary indexes on very wide tables (BTS 110 columns, Stack Exchange `posts`), FULLTEXT for Stack Exchange, Enron, Wikipedia, WideWorldImporters `searchdetails` and AdventureWorks `productreview`, SPATIAL for the NOT NULL geometry columns, no partitioning by default (FKs are incompatible), opt-in `indexes-partitioned.sql` for NYC taxi and TPC-DS `store_sales`.
* **Verification**: `tests/indexes.yaml` versus `INFORMATION_SCHEMA.STATISTICS`; `EXPLAIN FORMAT=JSON` of every smoke query must not show `access_type: "ALL"` on the tables named in `tests/explain.yaml` (tables under 100 rows exempt).

## 10. Knowledge bundle maintenance

The bundle at `knowledge/` conforms to **OKF v0.2** ([spec record](knowledge/sources/okf-spec-v0-2.md)); the root `knowledge/index.md` declares `okf_version: "0.2"`. The full rules are in [knowledge-bundle-conventions](knowledge/runbooks/knowledge-bundle-conventions.md) and [executor-discipline](knowledge/runbooks/executor-discipline.md); this section is the summary.

### 10.1 Layout and concept types

| Directory | `type` | Holds |
|---|---|---|
| `datasets/` | `Dataset` | one record per dataset: artifact, shape, hazards, conversion path, tests, tier, license |
| `licenses/` | `License` | one record per license text, with the verbatim attribution wording and every dataset it applies to |
| `tools/` | `Tool` | one record per build-time tool or product, with version, license, verified behaviour, limits |
| `decisions/` | `Decision` | question, options, evidence links, outcome, status |
| `sources/` | `Source` | one record per source artifact read (a document, a repository at a commit, a manual page set), every URL read listed under `sources`, with access date, version, excerpt, what it decided |
| `runbooks/` | `Runbook` | repeatable procedures (conventions, executor discipline, IPv6/privilege handling) |
| `questions/` | `Open Question` | unresolved facts with the cheapest resolving experiment |

Spec fields used on every record: `type`, `title`, `description`, `resource`, `tags`, `status` (`draft|stable|deprecated`), `generated {by, at}`, `verified [{by, at}]` (present only when the record is verified), `sources [{resource, title, accessed, version}]`, optional `stale_after`. Project field: `trust: verified | inferred | open`, which mirrors the spec's trust tiers (a record with `verified` entries is machine-confirmed; one without is unverified) and makes the distinction visible to humans.

### 10.2 Templates

Research record (`sources/`):

```markdown
---
type: Source
title: <document title>
description: <one sentence>
resource: <URL>
tags: [...]
status: stable
trust: verified
generated: { by: "<agent>/<model>", at: "<ISO 8601>" }
verified: [{ by: "<agent>/<model>", at: "<ISO 8601>" }]
sources: [{ resource: <URL>, title: <title>, accessed: <YYYY-MM-DD>, version: <tag/commit/snapshot> }]
---
# What was read
# Relevant excerpt
> verbatim quotation
# What it was used to decide
[link](/decisions/....md)
```

Decision record (`decisions/`): `# Question`, `# Options considered` (each with the reason it lost), `# Evidence` (links to sources/tools/datasets), `# Outcome`, `# Status` (`accepted | pending | superseded-by <link>`).

### 10.3 Rules the executor follows

* **Append to `log.md`** at the end of every working session and immediately after any deviation, under today's ISO date, newest first, with bold verbs **Creation**, **Update**, **Verification**, **Deviation**, **Deprecation**.
* **Update versus create**: a new fact about an existing dataset or tool updates that record (bump `generated.at`, add the source, add a `verified` entry when a command produced the fact). A newly read source artifact creates a new `sources/` record (pages of the same artifact are listed under its `sources`). A new judgment call creates a `decisions/` record; a changed one deprecates the old record with `superseded-by`.
* **Deviation from the plan**: dated **Deviation** log entry → new or updated decision record with evidence → PLAN.md edited to point at that record. Never silently.
* **Verified versus inferred**: `trust: verified` requires an authoritative source in `sources` or a recorded command output; estimates and reasoning stay `trust: inferred`; questions are `trust: open` with `status: draft`. A verified record may carry inferences, each prefixed **Inferred:** (or under a `# Inferred` heading); `trust` describes the load-bearing claims. A record whose central claim is inferred is `trust: inferred`. The phrase "from memory" is allowed in a verified record only inside such a marked passage.
* **Generated files**: `datasets/<db_name>/LICENSE` and `PROVENANCE.md` are produced by `scripts/gen_provenance.py` exactly as specified in §8.2 (`dataset.yaml` → knowledge records → license records, measurements only when a baseline exists), so the knowledge record is the single source of truth. CI fails if the knowledge-derived part of a generated file is stale.

### 10.4 Validation in CI

`scripts/okf_check.py` (committed now, wired into the `okf` workflow in task P-01) runs on every push in a few seconds and enforces, with PyYAML as its only dependency:
1. every non-reserved `.md` under `knowledge/` parses as terminated YAML frontmatter with a non-empty `type` (the spec's conformance rule);
2. `status`, `trust`, `generated.at` are present and well-formed; `verified` is present iff `trust: verified`; `tags` are strings; no `sources[]` entry is marked "not read";
3. the required section headings per type exist in order; Dataset tier tags come from the vocabulary; a Decision's `# Status` agrees with its `status`/`trust`; a License has a non-empty `# Attribution`;
4. a `trust: verified` record says "from memory" only inside an **Inferred:** line;
5. every markdown link in every file (concepts, `index.md`, `log.md`) and every bundle path in `resource`/`sources[]` resolves; broken links are warnings while the root `index.md` says `bundle_status: draft` and errors once it says `stable` (R-02 flips it) or with `--strict-links`;
6. every `index.md` equals its generated form (`--write-index` regenerates, preserving the root intro paragraph);
7. `log.md` has only ISO-date headings, descending, and every bullet starts with an allowed bold verb.
If an official OKF validator exists at execution time it runs first (see [validator question](knowledge/questions/okf-validator-availability.md)); the script above remains as the project-specific check.
