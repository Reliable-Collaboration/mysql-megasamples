# Identity
* Proposed MySQL database: **`ssb`**; tables `lineorder, customer, supplier, part, date` (the paper's names; `date` is a non-reserved keyword in MySQL ([keywords](/sources/mysql-refman-9-7-keywords.md)) — the DDL quotes it as `` `date` `` anyway; ClickHouse also uses `date`).
* Defined by "Star Schema Benchmark Revision 3, June 5, 2009, Pat O'Neil, Betty O'Neil, Xuedong Chen, UMass/Boston" ([paper record](/sources/umb-star-schema-benchmark-rev3.md)): TPC-H denormalised — LINEITEM+ORDERS → LINEORDER, PARTSUPP dropped, NATION/REGION folded into customer/supplier, a DATE dimension added, comments dropped.
* Not a TPC benchmark; no trademark issue, but the generator is TPC-derived (see License).

# Native format and friendlier forms
`dbgen -s SF -T a` writes `customer.tbl, part.tbl, supplier.tbl, date.tbl, lineorder.tbl`: pipe-delimited, trailing `|` unless built with `-DEOL_HANDLING=ON`, dates as integers `YYYYMMDD` unless `-DYMD_DASH_DATE=ON`; optional `-DCSV_OUTPUT_FORMAT=ON`. Sample customer row: `1|Customer#000000001|j5JsirBM9P|MOROCCO  0|MOROCCO|AFRICA|25-989-741-2988|BUILDING|`. No SQL dump or CSV exists upstream; ClickHouse's doc is the closest "friendly" reference (DDL + queries), not data.

Encoding: "Text is in 8-bit ASCII" (paper) — nation/region names upper-case ASCII, `Customer#…`, `Supplier#…`, `Part` names are colour pairs; no non-ASCII. MySQL DDL (types from `doc/ssb.ddl`, sizes per paper; VARCHAR(1) flags become CHAR(1)):
```sql
CREATE TABLE `date` (d_datekey INT NOT NULL, d_date CHAR(18) NOT NULL, d_dayofweek VARCHAR(9) NOT NULL, d_month VARCHAR(9) NOT NULL, d_year INT NOT NULL, d_yearmonthnum INT NOT NULL, d_yearmonth CHAR(7) NOT NULL, d_daynuminweek INT NOT NULL, d_daynuminmonth INT NOT NULL, d_daynuminyear INT NOT NULL, d_monthnuminyear INT NOT NULL, d_weeknuminyear INT NOT NULL, d_sellingseason VARCHAR(12) NOT NULL, d_lastdayinweekfl CHAR(1) NOT NULL, d_lastdayinmonthfl CHAR(1) NOT NULL, d_holidayfl CHAR(1) NOT NULL, d_weekdayfl CHAR(1) NOT NULL, d_iso_date DATE AS (STR_TO_DATE(d_datekey, '%Y%m%d')) STORED, PRIMARY KEY (d_datekey));
CREATE TABLE customer (c_custkey INT NOT NULL, c_name VARCHAR(25) NOT NULL, c_address VARCHAR(25) NOT NULL, c_city CHAR(10) NOT NULL, c_nation CHAR(15) NOT NULL, c_region CHAR(12) NOT NULL, c_phone CHAR(15) NOT NULL, c_mktsegment CHAR(10) NOT NULL, PRIMARY KEY (c_custkey));
CREATE TABLE supplier (s_suppkey INT NOT NULL, s_name CHAR(25) NOT NULL, s_address VARCHAR(25) NOT NULL, s_city CHAR(10) NOT NULL, s_nation CHAR(15) NOT NULL, s_region CHAR(12) NOT NULL, s_phone CHAR(15) NOT NULL, PRIMARY KEY (s_suppkey));
CREATE TABLE part (p_partkey INT NOT NULL, p_name VARCHAR(22) NOT NULL, p_mfgr CHAR(6) NOT NULL, p_category CHAR(7) NOT NULL, p_brand1 CHAR(9) NOT NULL, p_color VARCHAR(11) NOT NULL, p_type VARCHAR(25) NOT NULL, p_size INT NOT NULL, p_container CHAR(10) NOT NULL, PRIMARY KEY (p_partkey));
CREATE TABLE lineorder (lo_orderkey BIGINT NOT NULL, lo_linenumber TINYINT NOT NULL, lo_custkey INT NOT NULL, lo_partkey INT NOT NULL, lo_suppkey INT NOT NULL, lo_orderdate INT NOT NULL, lo_orderpriority CHAR(15) NOT NULL, lo_shippriority CHAR(1) NOT NULL, lo_quantity TINYINT NOT NULL, lo_extendedprice INT NOT NULL, lo_ordtotalprice INT NOT NULL, lo_discount TINYINT NOT NULL, lo_revenue INT NOT NULL, lo_supplycost INT NOT NULL, lo_tax TINYINT NOT NULL, lo_commitdate INT NOT NULL, lo_shipmode CHAR(10) NOT NULL, PRIMARY KEY (lo_orderkey, lo_linenumber));
```
(The generated column `d_iso_date` is our addition for convenience; `lo_orderdate`/`lo_commitdate` stay INT `YYYYMMDD` as in the paper so the canonical queries' `lo_orderdate = d_datekey` join is unchanged. `doc/ssb.ri`'s single-column `lineorder(lo_orderkey)` PK is wrong — the paper's compound key is used.)

# Conversion path
**Chosen** ([decision](/decisions/ssb-generator-path.md)): a builder stage (gcc + cmake) clones ssb-dbgen at the pinned commit, `cmake -B build -DEOL_HANDLING=ON && cmake --build build`, and the resulting `dbgen` + `dists.dss` are copied into the loader image (~100 KB); `make gen-ssb SF=1` runs `dbgen -b dists.dss -s $SF -T a -v`, computes `baseline.json` from the `.tbl` files with `scripts/canon.py`, loads with `LOAD DATA LOCAL INFILE … FIELDS TERMINATED BY '|'` (no trailing pipe thanks to EOL_HANDLING=ON; else `LINES TERMINATED BY '|\n'`), dimensions first, then lineorder pre-sorted by (lo_orderkey, lo_linenumber) (dbgen order), then `indexes.sql`, `constraints.sql`, `ANALYZE`. The 13 queries are shipped as `datasets/ssb/queries/q1_1.sql … q4_3.sql` written from the paper (authors' own SQL, 10–20 lines each).

# Type-mapping hazards
1. `d_date` "December 22, 1998" is 18 chars (paper "fixed text, size 18"); `doc/ssb.ddl` says VARCHAR(19) — use CHAR(18)? Keep **VARCHAR(19)** to be safe until measured.
2. Trailing pipe (default build) — see conversion path.
3. Integer dates: `lo_orderdate` 19920101..19981231 fits INT; joins to `date.d_datekey` are integer-only (fast); users wanting real dates use `d_iso_date`.
4. `lo_extendedprice` ≤ 55,450 (×100 cents? the paper says "numeric ≤ 55,450"; generator emits integers — verify magnitude), `lo_ordtotalprice` ≤ 388,000, `lo_revenue = lo_extendedprice*(100-lo_discount)/100` — all INT; the flights' `sum(lo_extendedprice*lo_discount)` and `sum(lo_revenue - lo_supplycost)` overflow INT but MySQL SUM returns DECIMAL — fine.
5. `TINYINT` for lo_linenumber/quantity/discount/tax and the flag CHAR(1)s are our narrowing (paper ranges 1–7, 1–50, 0–10, 0–8) — record in PROVENANCE; digests cast all to text so widths do not matter.
6. Queries: all 13 are plain SQL-92 (comma joins, BETWEEN, GROUP BY, ORDER BY) and need no MySQL edits (**Inferred** from the text in the [ClickHouse record](/sources/clickhouse-docs-star-schema-benchmark.md); verify by running).

# Indexing
* PKs as in the DDL; `date` is 2.5 K rows, `supplier` 2 K → small-table exemption for EXPLAIN.
* `indexes.sql`: `lineorder (lo_orderdate)`, `lineorder (lo_custkey)`, `lineorder (lo_suppkey)`, `lineorder (lo_partkey)`, `lineorder (lo_commitdate)`; `customer (c_region, c_nation, c_city)`, `supplier (s_region, s_nation, s_city)`, `part (p_category, p_brand1)`, `part (p_mfgr)`, `date (d_year)`, `date (d_yearmonthnum)`, `date (d_yearmonth)`, `date (d_weeknuminyear, d_year)` — each justified by a flight (Q1 by year/yearmonthnum/week, Q2 by category/brand + supplier region, Q3 by customer/supplier region/nation/city, Q4 by mfgr/category).
* `constraints.sql`: `lineorder → customer, supplier, part`, `lineorder(lo_orderdate) → date`, `lineorder(lo_commitdate) → date` (per `doc/ssb.ri`). Orphans expected 0 — **Inferred** (lo_commitdate could fall outside the 7-year DATE range as in TPC-H where commit dates extend past 1998-12-31? TPC-H l_commitdate max is 1998-10-31, inside range; verify with the orphan check before declaring the FK).

# Tests and expected values
* Counts at SF=1: customer 30,000; supplier 2,000; part 200,000; date ≈ 2,556; lineorder ≈ 6,000,000 (exact values recorded at first generation — [question](/questions/ssb-sf1-row-counts.md)).
* Selectivity sanity from the paper: Q1.1 selects ≈ 116,883 lineorder rows at SF=1 (FF 0.0194805), Q1.2 ≈ 3,896 — assert `COUNT(*)` with the Q1.1/Q1.2 predicates within ±2%.
* All 13 queries return non-empty results and Q1.x return one row; digests per the [checksum method](/decisions/test-checksum-method.md) from the `.tbl` files vs MySQL.
* EXPLAIN: Q1.1 must use `lineorder(lo_orderdate)` or a `date` range; Q3.1 must not full-scan `customer`.
