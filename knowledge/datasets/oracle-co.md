# Conversion path
Python script parser → MySQL (path (a) in [the decision](/decisions/oracle-conversion-path.md)). Parser must handle: multi-line quoted literals, `''` escapes inside JSON text, `UTL_RAW.CAST_TO_RAW(` wrapper (strip → JSON string), `TO_TIMESTAMP(` with 9 fractional digits, column-list INSERTs.

# Type-mapping hazards
* `INTEGER GENERATED BY DEFAULT ON NULL AS IDENTITY` → `INT NOT NULL AUTO_INCREMENT`; insert explicit ids, MySQL then continues from max+1, matching the upstream `START WITH LIMIT VALUE` reset.
* **`order_tms TIMESTAMP` with 9-digit literals → `DATETIME(6)`**: MySQL keeps at most 6 digits and *rounds* by default, truncates under `TIME_TRUNCATE_FRACTIONAL` ([MySQL fractional seconds](/sources/mysql-refman-9-7-fractional-seconds.md)); Oracle's own behaviour for a `TIMESTAMP` (precision 6) receiving a 9-digit literal was not verified. The converter must truncate to 6 digits itself before emitting the literal so the outcome does not depend on server sql_mode; record the rule in the baseline ([question](/questions/oracle-co-json-and-timestamp-fidelity.md)). Use `DATETIME(6)`, not `TIMESTAMP(6)` (MySQL TIMESTAMP is zone-shifted and limited to 2038).
* `product_details BLOB IS JSON` → `JSON`: validation on insert is equivalent; MySQL stores a binary form with sorted keys, so `SELECT product_details` returns keys in a different order than Oracle's stored text (cosmetic) and duplicate keys would collapse (none expected — verify in the same question). **Inferred:** `JSON_TABLE(... NESTED PATH '$.reviews[*]' COLUMNS(...))` is valid MySQL syntax (from memory; one-line check in the fidelity question), so `product_reviews` ports almost verbatim.
* `NUMBER(9,6)` lat/long → `DECIMAL(9,6)`; `NUMBER(10,2)` → `DECIMAL(10,2)`; `VARCHAR2(n CHAR)` → `VARCHAR(n)` (character semantics match); `BLOB` logo/image → `LONGBLOB` NULL; `DATE` `logo_last_updated`/`image_last_updated` → `DATETIME` (no data; keep Oracle semantics).
* `order_status`/`shipment_status` CHECK lists → CHECK constraints (or ENUM; CHECK keeps upstream semantics and error messages closer).
* Multi-line addresses: keep `\n` inside the string; the naming/quoting layer must not collapse whitespace.

# Programmable objects
| object | action | reason |
|---|---|---|
| view `customer_order_products` | port with change | `LISTAGG(... ON OVERFLOW TRUNCATE '...' WITH COUNT) WITHIN GROUP (ORDER BY line_item_id)` → `GROUP_CONCAT(product_name ORDER BY line_item_id SEPARATOR ', ')`; overflow behaviour differs (MySQL silently cuts at `group_concat_max_len`, default 1024 — set 65535 in the session or accept; longest order has few items) |
