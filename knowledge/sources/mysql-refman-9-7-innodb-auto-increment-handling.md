# What was read
https://dev.mysql.com/doc/refman/9.7/en/innodb-auto-increment-handling.html, accessed 2026-09-02; version: MySQL 9.7 manual, section 17.6.1.6.

# Relevant excerpt
* "Interleaved lock mode (innodb_autoinc_lock_mode=2) is the default."
* Mode 2: "no 'INSERT-like' statements use the table-level AUTO-INC lock, and multiple statements can execute at the same time." "there may be gaps in the auto-increment values generated by 'bulk inserts,' but only if there are concurrently executing 'INSERT-like' statements." Bulk inserts include `INSERT ... SELECT`, `REPLACE ... SELECT`, and `LOAD DATA`.
* Mode 2 "is not safe when using statement-based replication" (irrelevant here: no replication).

# What it was used to decide
[LOAD DATA tool record](/tools/load-data-infile.md): no configuration change is needed for the bulk-load recommendation `innodb_autoinc_lock_mode=2`; parallel loaders into one table may leave auto-increment gaps, so surrogate keys are assigned by the converter, not by AUTO_INCREMENT, whenever deterministic ids are required.
