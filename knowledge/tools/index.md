# tools

## Concepts
* [SQLBI Contoso Data Generator V2 (2.0.1)](contoso-data-generator-v2.md) - .NET 8 console tool (MIT) that generates the Contoso V2 star schema (customer, date, product, store, currencyexchange, sales, orders, orderrows) as CSV/Parquet/Delta for any OrdersCount; constant-seeded RNG; pre-built sizes published as 7z archives.
* [Docker multi-stage build, BuildKit mounts, and the pre-populated data directory path](docker-build-multistage.md) - How the final image is assembled from a builder stage that runs mysqld, what the official entrypoint does with an existing datadir, and the VOLUME/anonymous-volume cost to measure.
* [DuckDB tpch and tpcds extensions (built-in dbgen 2.17.3 and dsdgen 2.10.0)](duckdb-tpch-tpcds-extensions.md) - Generate TPC-H/TPC-DS data at any (fractional) scale factor inside DuckDB without a C toolchain, then COPY to pipe-delimited files for LOAD DATA or ATTACH MySQL directly; the generator code is TPC-EULA-licensed inside an MIT project.
* [DuckDB (Parquet/CSV reader and MySQL writer)](duckdb.md) - Single-binary analytical engine used to read TLC Parquet and the bike/BTS CSVs, reshape them, and emit MySQL-ready CSV; its MySQL extension can also write straight into MySQL.
* [GitHub, GitHub Actions, ghcr.io and Docker Hub limits](github-limits.md) - Hard numbers that size the repository, the release assets, the CI build and the registry image: 100 MiB file block, < 1 GB repo guidance, 2 GiB per release asset with no total, LFS 10 GiB/month bandwidth then metered, 4 vCPU/16 GB/14 GB SSD runners with 6-hour jobs, 10 GB ghcr layers, Docker Hub 100 anonymous pulls per 6 hours.
* [archive.org as a secondary mirror for upstream artifacts and release bundles](internet-archive-mirroring.md) - The ia CLI / IAS3 API let the project upload redistributable upstream archives and its own bundles to archive.org items; uploads must be non-infringing (Terms of Use not readable this session); throughput and availability are undocumented, so archive.org is a fallback URL in the manifest, never the only source.
* [jafgen (Jaffle Shop Generator) 0.4.14](jafgen.md) - Python CLI that simulates a jaffle shop and writes raw_*.csv files for customers, orders, items, products, supplies, stores, tweets; Apache-2.0; not idempotent (no seed option).
* [MySQL 9.7 LOAD DATA (server-side and LOCAL) and the bulk-load settings](load-data-infile.md) - The ingestion primitive for every converted dataset: LOCAL versus server-side semantics, secure_file_priv in the official image, the converter TSV contract (\N NULLs, backslash escapes), strict-versus-nonrestrictive loading, and the documented InnoDB bulk-load settings; mysqldump --tab as fallback exporter, mysqlpump gone.
* [MediaWiki dump parsing (pages-articles XML via mwxml or iterparse; .sql.gz tables via mwsql or direct load)](mediawiki-xml-dump-parsing.md) - How the Simple English Wikipedia dumps get into MySQL — stream the XML for page text and revisions, and load the MediaWiki-produced .sql.gz files directly after DDL fix-ups.
* [SQL Server Linux container (mcr.microsoft.com/mssql/server)](mssql-server-container.md) - Microsoft's official Ubuntu-based SQL Server image, used only at build time to restore WideWorldImporters .bak files (and optionally AdventureWorks .bak) before exporting to MySQL; Developer edition by default, EULA acceptance required, amd64 only, 2 GB RAM minimum.
* [MySQL 9.7 behaviour notes for conversions](mysql-9x-behaviour-notes.md) - Verified server behaviours that shape every schema port: utf8mb4/utf8mb4_0900_ai_ci defaults, caching_sha2_password only, spatial SRID rules, JSON, CHECK constraints, generated columns, identifier limits and case sensitivity, sql_mode, temporal/decimal/bit ranges, no UUID or datetimeoffset type, FULLTEXT tuning, invisible columns/indexes, partitioning limits, size and integrity statements, and what changed in 9.x.
* [MySQL classic_hashing component (MD5/SHA1 on 9.6+)](mysql-classic-hashing-component.md) - Since MySQL 9.6.0 MD5() and SHA1() live in an optional component; upstream checksum scripts that call MD5()/SHA() fail on the 9.7 image unless the component is installed or the scripts are rewritten to SHA2().
* [Official mysql Docker image](mysql-docker-official-image.md) - Base image for the final stage; tag family, initdb behaviour, variants, and the verification step for the 9.7.3 tag.
* [MySQL Server 9.7 LTS](mysql-server-9-7.md) - The target database engine; LTS status, support window, and the point release to pin.
* [MySQL Shell dump format as the ports read it (util.dumpSchemas, mysqlsh 9.7.1)](mysql-shell-dump-format.md) - What a build/mysql/dumps/<dataset>/ directory holds and the rules the port reader relies on -- UTC timestamps, base64 binary columns, chunk file naming, generated columns absent -- each observed on this project's dumps.
* [MySQL Shell 9.7 utilities: importTable, dump/loadDump, copy](mysql-shell-utilities.md) - mysqlsh 9.7.1 is already in the official mysql:9.7 image; util.importTable is the parallel LOAD DATA LOCAL loader, util.dumpSchemas/loadDump is the interchange format with deferred secondary indexes, util.copy* streams between servers; all need local_infile=ON.
* [MySQL Workbench Migration Wizard (8.0.47)](mysql-workbench-migration-wizard.md) - GUI wizard for ODBC-reachable sources (SQL Server, PostgreSQL, Sybase ASE, SQLite, Access, SQL Anywhere, generic ODBC); copies data with the bundled wbcopytables helper; rejected for the unattended build because schema conversion is interactive and non-MySQL programmable objects are only copied as comments.
* [Oracle Database Free container (container-registry.oracle.com/database/free, alternative gvenzl/oracle-free)](oracle-database-free-container.md) - The only way to execute Oracle-specific install scripts (OE/PM object types, XMLType, SQLcl LOAD) during the build; sizes, licensing, arm64 support, login requirement, and connection details verified for an optional build-oracle Compose profile.
* [pgloader (v3.6.x SBCL, v4 Clojure rewrite in progress)](pgloader.md) - Loads CSV/fixed/dBase/IXF/archives and MySQL/SQLite/MS SQL Server/PostgreSQL/Redshift into PostgreSQL only; PostgreSQL-licensed; rejected for this project because MySQL is never a target and DuckDB/bcp cover the MSSQL-to-CSV step directly.
* [PostgreSQL official Docker image (postgres:18.6-bookworm)](postgres-docker-official-image.md) - The image the PostgreSQL engine is built from; where its data directory lives, how its entrypoint treats an existing one, and what was pulled.
* [Python conversion stack](python-conversion-stack.md) - Pinned Python packages for converters, verifiers and generators, chosen for permissive licenses and MySQL 9.7 compatibility.
* [CSV loading notes for this group's flat-file datasets (LOAD DATA vs generated INSERTs)](smallcsv-load-data-infile.md) - Dataset-specific CSV facts verified for DS3, Jaffle Shop, Lahman, Contoso, Titanic, Iris and Penguins (headers, quoting, NA tokens, date formats, BOMs) and the loader recipe they imply; generic MySQL LOAD DATA / secure_file_priv behaviour is covered by the tools agent.
* [SQLcl and python-oracledb as Oracle-side load/export tools](sqlcl-and-python-oracledb.md) - SQLcl (Java CLI, OTN developer license) provides the LOAD command the SH installer requires and csv/json/insert SQLFORMAT spooling; python-oracledb (UPL/Apache, Thin mode, no Instant Client) is the preferred programmatic exporter for the optional Oracle verification profile.
* [sqlcmd and bcp (mssql-tools18 / go-sqlcmd)](sqlcmd-bcp.md) - Command-line query and bulk-export tools for SQL Server; bcp (proprietary, ODBC-based, in mssql-tools18) is the export path for .bak-only datasets, go-sqlcmd (MIT) is the redistributable query client. Records the UTF-8 export rules on Linux and bcp's no-quoting hazard.
* [ssb-dbgen (Star Schema Benchmark data generator, eyalroz unified fork)](ssb-dbgen.md) - CMake-built C generator derived from TPC-H dbgen that writes the five SSB tables as pipe-delimited .tbl files; no license file, TPC EULA applies by derivation; no query generator.
* [Stack Exchange data dump XML parsing (streaming iterparse; own MySQL loader)](stackexchange-xml-parsing.md) - How the per-site 7z archives of `<row .../>` XML files are read and loaded into MySQL, and what existing converters teach us.
* [Enron maildir parsing with the Python `email` standard library](text-enron-maildir-parsing.md) - Build-time parser for the CMU Enron maildir tree — one RFC 822 file per message, no attachments — into messages/recipients/mailbox tables.
* [TPC-C-derived loaders for MySQL — tpcc-mysql, sysbench-tpcc, HammerDB TPROC-C](tpcc-implementations.md) - Evaluation of the three open-source ways to create and populate a TPC-C-derived schema in MySQL, with license, schema, row counts, determinism and container fit.
* [tpcds-kit (TPC-DS dsdgen/dsqgen 2.10.0, GitHub mirror by gregrahn)](tpcds-kit.md) - Reference C generator for the 24 TPC-DS tables and the 99 query templates with dialect files; integer scale factors only; deterministic RNG seed; ships a MySQL test script.
* [tpch-kit (TPC-H dbgen/qgen 2.17.3, GitHub mirror by gregrahn)](tpch-kit.md) - Reference C generator for TPC-H data and the 22 query templates with SF=1 answers; built with make in a builder stage; output is pipe-delimited .tbl with a trailing pipe.
