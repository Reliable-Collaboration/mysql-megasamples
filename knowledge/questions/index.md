## Concepts
* [Loaded InnoDB size and load time of tpch, tpcds, tpcc, ssb per scale factor / warehouse](benchmark-innodb-size-per-sf.md) - Only raw sizes are documented (TPC-H SF1 956 MB; TPC-DS SF1 ~1.2 GB inferred; TPC-C ~69 MB/warehouse inferred; SSB SF1 ~600 MB inferred); InnoDB with indexes is estimated at 1.5–3× raw.
* [May a converted copy of Citi Bike / Divvy trip data be redistributed in a public image?](citibike-divvy-redistribution.md) - Both Lyft bikeshare licences forbid publishing or distributing the data "as a stand-alone dataset"; this decides whether these two datasets can ship at all or must be user-fetched.
* [How far can each of the four database consoles be preconfigured without a manual step?](console-preconfiguration-limits.md) - Answered by measurement: phpMyAdmin and DbGate are fully preconfigurable, Adminer's login form is not, and CloudBeaver does start unattended -- through an undocumented conf/.cloudbeaver.auto.conf trigger plus an anonymous-team grant, not through anything the wiki describes.
* [Is Contoso Data Generator V2 output byte-identical across runs and platforms for the same config?](contoso-generator-determinism.md) - All RNGs are seeded with constants in source, but .NET Random(seed) algorithms differ between frameworks/versions and the engine mentions multithreading; the published csv-100k.7z may or may not match a regenerated set.
* [Do DuckDB's dbgen/dsdgen ports produce byte-identical rows to the C tools, and how fast is ATTACH-mysql insert versus LOAD DATA?](duckdb-generator-fidelity.md) - The chosen generator path relies on DuckDB's ports; identity with the reference C output and the NULL/DECIMAL/CHAR export behaviour are unverified.
* [How does DuckDB's MySQL extension physically write rows, and is it fast enough to skip CSV?](duckdb-mysql-write-throughput.md) - The docs never say whether writes are batched INSERTs or LOAD DATA; this decides whether the loader needs a CSV intermediate at all.
* [What license covers the DS3 Small CSV data files (generator output)?](dvdstore-generated-data-license.md) - The DS3 kit is GPL-2.0-or-later, but the committed CSVs are the output of the generators; GPL section 0 says output is covered only if it is a "work based on the Program", and Dell never labelled the data separately.
* [Enron header anomalies — charset of non-ASCII bodies, Date offsets/bogus years, Message-ID uniqueness](enron-header-anomalies-charset-dates-message-id.md) - The parsing plan assumes cp1252 fallbacks, `-0700 (PDT)` dates with a few bogus years, and one Message-ID per file; none is verified from an authoritative source.
* [What did the ISI Shetty/Adibi Enron MySQL page offer, and is any copy still authoritative?](enron-isi-mysql-dump-availability.md) - The live page is blocked (403) and Wayback rate-limited the 2013 snapshot; only a third-party "repaired" copy is reachable.
* [What are the sha256 of enron_mail_20150507.tar.gz and the exact file count?](enron-tarball-checksum-and-message-count.md) - CMU publishes no checksum and says only "about 0.5M messages"; two third-party READMEs say 517,401 files.
* [Iris licensing - accept UCI's CC BY 4.0 with attribution, or ship the scikit-learn/R corrected copy (BSD-3) as facts?](iris-uci-cc-by-vs-public-domain.md) - UCI labels Iris CC BY 4.0 (not public domain as commonly assumed); the same 150 measurements are shipped by scikit-learn under BSD-3-Clause and by R's datasets package; the data are 1936 facts.
* [Under what license are the new dbt-labs/jaffle-shop seeds and the S3 long_term_dataset distributed?](jaffle-shop-new-repo-license.md) - dbt-labs/jaffle-shop (main, 2026-07) has no LICENSE file and GitHub reports none; the 6-year S3 CSVs carry no license statement either. Only jaffle-shop-classic and jafgen are Apache-2.0.
* [How can the Lahman 2025 CSV set be fetched non-interactively (or should it be vendored)?](lahman-box-direct-download.md) - SABR distributes the CSVs via a Box shared folder without a static download URL; guessed shared/static .zip links return 404; sizes are unknown.
* [Do the MariaDB-generated simplewiki .sql.gz dumps load unchanged into MySQL 9.7?](mediawiki-sql-dump-ddl-compatibility-mysql-9-7.md) - Four constructs in the dump headers are MariaDB-isms or deprecated MySQL syntax; each needs a one-minute test on the target server before the build script is written.
* [Does the 2012 AdventureWorksLT script zip produce the same data as the LT2016-LT2022 .bak files (and how does LT2025 differ)?](mssql-adventureworks-lt-script-vs-bak-parity.md) - The only SQL-Server-free form of AdventureWorksLT is the 2012 release zip; the README says 2012-2022 AdventureWorks builds differ only in name/compatibility level, and 2025 adjusted dates, but this was stated for the OLTP database, not explicitly for LT.
* [AdventureWorks OLTP/DW - exact row counts of the large CSVs, the ProductReview line anomaly, and decoders for hierarchyid/geography](mssql-adventureworks-row-counts.md) - Answered for the OLTP half - all 69 tables counted on a real load, ProductReview confirmed at 4 rows, and both binary decoders verified over every row; the DW counts remain for task X-01.
* [Can a WideWorldImporters .bacpac be read without SQL Server (to allow arm64 builders)?](mssql-bacpac-readable-without-sql-server.md) - A .bacpac is documented only as an importable DacFx package ("compressed but not encrypted"); its internal layout (zip with model.xml and per-table BCP-native data files) is not documented on the page read, so direct parsing is inferred and unverified.
* [bcp on Linux - confirm UTF-8 output with -c, the NULL/empty-string sentinel, safe multi-character terminators, and the 2022 container's bcp flag set](mssql-bcp-linux-export-encoding-and-escaping.md) - Documentation establishes that -C is Windows-only, the ODBC driver defaults narrow data to UTF-8, and bcp never quotes; the concrete command line for exporting WWI NVARCHAR(MAX)/JSON/geography columns losslessly has not been executed.
* [Northwind Categories.Picture / Employees.Photo - strip the OLE wrapper or keep raw bytes?](mssql-northwind-picture-ole-header.md) - All 17 image literals in instnwnd.sql begin with 151C2F00020000000D000E00 rather than a BMP/GIF signature; this is believed (not verified) to be the 78-byte Access OLE Object header around a Windows bitmap.
* [WideWorldImporters and WideWorldImportersDW - published row counts and loaded sizes do not exist; measure at export](mssql-wideworldimporters-row-counts.md) - No Microsoft page read publishes WWI row counts; the dataset records' values were inferred and had to be replaced by counts taken in SQL Server during the export step. Answered on 2026-09-03 - all 19 OLTP figures were exact, 4 of the DW's 14 were not.
* [Exactly which of the 22 qgen-generated TPC-H queries need MySQL edits, and does utf8mb4_bin reproduce the reference ordering?](mysql-tpch-query-port-syntax.md) - Community ports show Q1 needs the interval precision "(3)" removed; the rest is inferred to run unchanged with the POSTGRESQL dialect's "limit N".
* [Does NYC Open Data actually permit unrestricted redistribution of TLC trip data?](nyc-open-data-reuse-terms.md) - The Open Data FAQ says there are no restrictions; the NYC.gov Terms of Use it incorporates reserve all rights. The tension is unresolved on the City's own pages.
* [Is there an OKF v0.2 validator we can run in CI?](okf-validator-availability.md) - Neither GoogleCloudPlatform/open-knowledge-format nor knowledge-catalog ships a validator (only the reference agent has an OKFDocument.validate that requires a `type`); the PyPI `okf` package is an unrelated stub; the repository owns its own checker, megasamples/okf_check.py.
* [CO fidelity — 9-digit timestamps, JSON key normalisation, and GROUPING SETS in MySQL 9.7](oracle-co-json-and-timestamp-fidelity.md) - Three details where MySQL may render CO data or views differently from Oracle; each is a one-command experiment.
* [OE extras — carry the 132 XML purchase orders, add POINT SRID 4326 columns, flatten categories_tab?](oracle-oe-xml-purchase-orders-scope.md) - Three optional enrichments of oracle_oe whose value depends on cheap checks (XML structure, MySQL 4326 axis order, OC category data) not performed during research.
* [Do the SH CSV files reproduce the published row counts, and does LOAD DATA need the padding/NULL pre-pass?](oracle-sh-csv-row-counts-and-padding.md) - 918,843 sales rows and the other counts are published inside sh_install.sql but the CSVs were not downloaded during research; sales.csv is space-padded to 80 columns and NULL strings appear as "".
* [Does downloads.mysql.com regenerate sakila-db.zip, invalidating a pinned checksum?](sakila-download-checksum-drift.md) - The archive's HTTP Last-Modified (2026-08-31) is newer than the manual revision (2026-08-04) and zip entries are dated 2026-09-01, suggesting periodic regeneration.
* [How many <page> elements are in simplewiki-20260901-pages-articles.xml.bz2 and which namespaces?](simplewiki-pages-articles-page-count.md) - site_stats gives 947,771 pages in the page table and 284,761 content articles, but the pages-articles file (subject pages, no talk) has an unpublished count that sets the revision/text row baseline.
* [Exact ssb-dbgen row counts at SF=1 (lineorder, date), fractional SF behaviour, and lo_commitdate range](ssb-sf1-row-counts.md) - The paper gives SF×6,000,000, SF×30,000, SF×2,000, 200,000×(1+log2 SF) and "7 years of days"; exact generated counts (6,001,215? 2,556?) are inferred.
* [Will the archive.org Stack Exchange item remain available, and should the project mirror the chosen .7z files?](stackexchange-archive-org-item-persistence.md) - The build depends on a 2024 upload that Stack Overflow said it would prefer not to see mirrored; the item has not been touched since 2025-06-24, but nothing guarantees it stays.
* [Row counts per XML file in dba.stackexchange.com.7z (2024-04-02 snapshot) and the small core site](stackexchange-dump-row-counts-2024-04.md) - Only live 2026 totals exist; the exact April 2024 counts must be measured once and pinned as the test baseline.

* [Does the TPC EULA restrict redistribution of dbgen/dsdgen OUTPUT (the generated rows)?](tpc-eula-generated-data-redistribution.md) - The EULA licenses "the Software … and data files associated with such programs" but never mentions generated output; we ship none, but users and CI caches will.
