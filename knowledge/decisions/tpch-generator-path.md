# Question
How does `make gen-tpch SF=n` produce TPC-H rows for MySQL, given that the official tools are behind a registration form and every open copy is TPC-EULA-licensed?

# Options considered
1. **DuckDB `tpch` extension** (`CALL dbgen(sf)` → `COPY … (DELIMITER '|', HEADER false)` → `LOAD DATA`): no compiler, already in the loader image, fractional SF, partitioned generation, built-in queries and answers for SF 0.01/0.1/1; port of dbgen 2.17.3 with the EULA bundled. **Chosen.**
2. tpch-kit dbgen 2.17.3 compiled in a builder stage (`make MACHINE=LINUX DATABASE=POSTGRESQL`): the reference implementation itself; needs gcc/make in a build stage and `LINES TERMINATED BY '|\n'` for the trailing pipe; provides qgen with `limit N` and `answers/`. **Kept as cross-check and fallback.**
3. electrum/tpch-dbgen: older 2.14.0, no EULA copy, no POSTGRESQL dialect — rejected.
4. Official TPC-H_Tools_v3.0.1.zip: not automatable (form + e-mailed link) — rejected for the build; used by a human once to run the version-identity experiment.
5. DuckDB `ATTACH … (TYPE mysql)` direct inserts instead of files: simpler pipeline, but throughput and DECIMAL/CHAR fidelity unmeasured — deferred to the fidelity experiment; files are also what `baseline.json` is computed from.

# Evidence
* [tpch-kit record](/tools/tpch-kit.md), [DuckDB extensions record](/tools/duckdb-tpch-tpcds-extensions.md), [DuckDB source record](/sources/github-duckdb-tpch-tpcds-extension-source.md) (same 2.17.3 code, EULA present, SF1 Q1 answer equals the spec's).
* [download form](/sources/tpc-tools-download-request-form.md).
* [tier model](/decisions/tier-model.md) already puts duckdb in the loader image.

# Outcome
Option 1 by default; the first execution task generates SF 0.01 and SF 1 with both option 1 and option 2 and diffs the sorted `.tbl` output byte-for-byte and the Q1–Q22 results against `tpch_answers()` / `answers/`. If they differ, option 2 becomes the default (builder stage) and this record is superseded. Queries: produced at build time from tpch-kit `qgen -d -c -s 1` (POSTGRESQL dialect) plus a documented sed patch (remove `(3)` in Q1, none else expected), so no TPC query text is committed.
