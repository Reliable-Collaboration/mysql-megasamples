# Question
How does `make gen-ssb SF=n` produce the five SSB tables, given there is no DuckDB generator and the SSB forks are unlicensed TPC-H dbgen derivatives?

# Options considered
1. **eyalroz/ssb-dbgen @ ae1e254** built with CMake (`-DEOL_HANDLING=ON` so no trailing pipe, default `YYYYMMDD` integer dates) in a builder stage; binary + `dists.dss` + an EULA copy/legend copied into the loader image. Maintained (2025), portable build, unifies the forks. **Chosen.**
2. electrum/ssb-dbgen or vadimtk/ssb-dbgen (ClickHouse's choice): older makefile.suite builds, unmaintained, same lineage — rejected but interchangeable if option 1 fails to build.
3. Derive SSB tables from the generated TPC-H tables with SQL (denormalise lineitem⋈orders, fold nation/region): reuses `tpch`, no extra binary — rejected because SSB's dimension distributions (p_brand1/p_color/s_city/lo_revenue/lo_supplycost, 30,000 customers, 2,000 suppliers) are defined by the SSB generator, not derivable from TPC-H rows; results would not match the paper's selectivities.
4. Generate with DuckDB: no SSB extension exists — not available.

# Evidence
[ssb-dbgen record](/tools/ssb-dbgen.md); [paper](/sources/umb-star-schema-benchmark-rev3.md); [ClickHouse doc](/sources/clickhouse-docs-star-schema-benchmark.md); [TPC EULA](/licenses/tpc-eula.md) clauses 8/9 for shipping the compiled binary inside the loader image.

# Outcome
Option 1. The loader image carries `/opt/ssb-dbgen/{dbgen,dists.dss,LICENSE(EULA + legend)}`; `make gen-ssb SF=1` writes the five `.tbl` files, computes `baseline.json`, loads with plain `FIELDS TERMINATED BY '|'`. Queries: 13 files re-typed from the paper (verified against the ClickHouse listing). First execution task records exact SF=1 counts and checks fractional SF behaviour ([question](/questions/ssb-sf1-row-counts.md)).
